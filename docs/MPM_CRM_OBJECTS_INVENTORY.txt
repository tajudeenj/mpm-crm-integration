SECTION 1 — TABLES (9)
═════════════════════════════════════════════════════════════════════

  #   Table Name                      Purpose
  ─── ─────────────────────────────── ──────────────────────────────────────────
  1   CRM_MPM_API_CREDENTIALS         OAuth2 token URL, client_id, client_secret,
                                      wallet path/password, token cache.
                                      One row: CRED_CODE = APIC_PXRM

  2   CRM_MPM_API_REGISTRY            Master config — one row per service (13 rows).
                                      Holds APIC endpoint URL, record-type header,
                                      record-action header, source view, key column,
                                      JSON mapping name, callback target table,
                                      retry/timeout settings.

  3   CRM_MPM_API_FIELD_MAPPING       Maps Oracle view column → JSON path.
                                      Dot notation builds nested objects.
                                      e.g. SOURCE_COLUMN=COUNTRY_CODE →
                                           JSON_PATH=country.country_id
                                      One row per field per service mapping group.

  4   CRM_MPM_API_WATERMARK           Last processed LAST_UPDATE_DATE per service.
                                      Package reads WHERE filter_col > watermark.
                                      Advances per-row after each successful send.
                                      Reset to 2000-01-01 to reprocess all records.

  5   CRM_MPM_CRM_INTEGRATION_LOG     Full audit — one row per send attempt.
                                      Stores LEG 1 (ACK_REQUEST_ID, HTTP status,
                                      ACK_RESPONSE_TIMESTAMP, X_UNIQUE_ID) and
                                      LEG 2 (CRM_ENTITY_ID, CALLBACK_RESULT_CODE,
                                      CALLBACK_VALID_ERRORS, CALLBACK_DATE).
                                      FINAL_STATUS: PENDING→SENT→SUCCESS/FAILED/
                                      TIMEOUT/EXHAUSTED/VALIDATION_FAILED etc.

  6   CRM_MPM_JOB_RUN_HISTORY         One row per DBMS_SCHEDULER execution.
                                      Records job name, status, start/end time,
                                      records processed/success/failed.
                                      Also used by job-lock guard.

  7   CRM_MPM_ERROR_CODE_MASTER       Reference table for error/callback codes.
                                      Outbound: SUCCESS, AUTH_FAILED, CONN_FAILED,
                                      TIMEOUT, EXHAUSTED, UNKNOWN_ERROR etc.
                                      Callback: CB_0000, CB_1001, CB_1002, CB_1003.
                                      IS_RETRYABLE flag controls retry eligibility.

  8   CRM_MPM_UNIQUE_ID_CONFIG        Controls x-unique-id header format.
                                      CHANNEL_ID=817, TIMESTAMP_FORMAT, 
                                      SEQUENCE_DIGITS=4.
                                      No package recompile needed to change values.

  9   CRM_MPM_CALLBACK_AUDIT_LOG      Raw audit of every LEG 2 callback received.
                                      Written FIRST using AUTONOMOUS_TRANSACTION
                                      before any processing — survives rollback.
                                      Stores: SERVICE_NAME, X_UNIQUE_ID, CHANNEL_ID,
                                      REQUEST_ID, PROCESSING_STATUS, PROCESSING_MSG,
                                      MATCHED_LOG_ID, RESPONSE_SENT,
                                      STATUS_CODE_SENT, DESCRIPTION_SENT,
                                      RAW_PAYLOAD (full JSON from CRM).

                                       Checks cache first (TOKEN_CACHE_VALUE).
                                       Re-fetches only if expired (< 60s remaining).
                                       Calls UTL_HTTP with wallet before HTTPS.
                                       Parameters: p_cred_code IN VARCHAR2

SECTION 4 — PROCEDURES (6 inside PKG_CRM_INTEGRATION)
═════════════════════════════════════════════════════════════════════

  #   Procedure Name          Parameters                    Purpose
  ─── ─────────────────────── ───────────────────────────── ──────────────────
  1   BUILD_JSON_PAYLOAD      p_registry_id IN NUMBER       Reads CRM_MPM_API_
                              p_source_view IN VARCHAR2     FIELD_MAPPING for
                              p_key_col     IN VARCHAR2     this registry.
                              p_key_value   IN VARCHAR2     Fetches row from
                              Returns       CLOB            view via DBMS_SQL.
                                                            Builds nested JSON
                                                            using dot-path notation.
                                                            DATA_TYPE=JSON embeds
                                                            raw JSON arrays.

  2   SEND_TO_APIC            p_registry_id IN NUMBER       Full LEG 1 send:
                              p_key_value   IN VARCHAR2     1. Duplicate guard
                              p_txn_group   IN VARCHAR2     2. Build JSON payload
                              p_attempt_no  IN NUMBER       3. Get bearer token
                              p_log_id_out  OUT NUMBER      4. Generate x-unique-id
                                                            5. UTL_HTTP POST to APIC
                                                            6. Parse ACK (request_id,
                                                               status, description)
                                                            7. Log result to
                                                               INTEGRATION_LOG

  3   RUN_OUTBOUND_JOB        None                          Main scheduled job:
                                                            1. Job-lock guard
                                                            2. Loop all active
                                                               registry rows
                                                            3. Read view where
                                                               filter_col > watermark
                                                            4. Call SEND_TO_APIC
                                                               per row
                                                            5. Advance watermark
                                                               per-row (crash-safe)
                                                            6. Write JOB_RUN_HISTORY

  4   RUN_TIMEOUT_JOB         None                          Marks stale records:
                                                            Finds SENT/PENDING rows
                                                            older than TIMEOUT_MINUTES.
                                                            Sets FINAL_STATUS=TIMEOUT.
                                                            Sets EXHAUSTED when
                                                            retry count exhausted.

  5   RUN_RETRY_JOB           None                          Re-sends failed records:
                                                            Finds FAILED/TIMEOUT rows
                                                            where retry_count < max
                                                            and NEXT_RETRY_DATE elapsed.
                                                            Calls SEND_TO_APIC with
                                                            ATTEMPT_NO+1.
                                                            Same TRANSACTION_GROUP_ID.

  6   PROCESS_CRM_CALLBACK    p_service_name     IN  VARCHAR2   LEG 2 handler:
                              p_callback_payload IN  CLOB       Called by ESB when
                              p_result_out       OUT VARCHAR2   CRM fires callback.
                              p_status_code      OUT VARCHAR2   1. Audit log written
                              p_description      OUT VARCHAR2      FIRST (autonomous)
                              p_x_unique_id      IN  VARCHAR2   2. Validate service
                              p_channel_id       IN  VARCHAR2   3. Parse request_id
                                                                4. Find log row by
                                                                   ACK_REQUEST_ID
                                                                5. Map result_code
                                                                   → FINAL_STATUS
                                                                6. Update log
                                                                7. Return JSON to ESB
                                                                p_status_code values:
                                                                CB_0000 = Success
                                                                CB_1001 = Bad service
                                                                CB_1002 = No log match
                                                                CB_1003 = Exception
